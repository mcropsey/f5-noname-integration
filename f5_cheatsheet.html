Prerequisites
Before You Start Download iRule from Akamai API Security UI Akamai UI

You need the send-to-noname.tcl file before you can proceed. It is pre-baked with your source key UUID and engine hostname — without it you cannot complete Step 5.

  • Navigate to Settings → Integrations → Traffic Sources → F5
  • Click Add Integration, name it, select HSL, select your engine
  • Download and extract the Zip file — it contains send-to-noname.tcl
ℹ
SSL RequirementThis integration requires SSL Offloading or SSL Bridging on the F5. SSL Passthrough will NOT work — the iRule cannot read encrypted payloads.

Step 1 Create Engine Pool Pool

⚠
Do NOT use default https monitorThe engine is behind an AWS ALB. The default F5 https monitor sends the pool node IP as the Host header — the ALB returns 404, and all members show red. Use tcp for now, then apply the custom monitor in Step 1a below.
Step 1a · SSH Required Create Custom HTTPS Monitor tmsh
noname-https-monitor

The AWS ALB requires a correct Host header to route health check requests. Run these commands on the F5 via SSH to create a custom monitor that sends the proper hostname:

tmsh create ltm monitor https noname-https-monitor \ defaults-from https \ send "GET / HTTP/1.1\r\nHost: michaels-lab.nonamesec.com\r\nConnection: close\r\n\r\n" \ recv "HTTP" tmsh modify ltm pool \ noname-security-engine-https-pool \ monitor noname-https-monitor tmsh save sys config
✓
After running thisThe engine pool should turn green within ~30 seconds. If it stays red, test with: curl -vk https://michaels-lab.nonamesec.com

Step 4 Upload HSL iRule iRule
noname-hsl-https-logger

Navigate to Local Traffic → iRules → iRule List → Create. Paste the full contents of send-to-noname.tcl. Key values already embedded:

nn_poolnoname-security-hsl-https
nn_engine_hostnamemichaels-lab.nonamesec.com
nn_payload_max_size131072 (128 KB max)
nn_base64_source_key04f72d92-81f0-4c5f-8142-7f2b60142ac9
nn_engine_url/engine?message-format=base64
ℹ
Pre-4.0.0 iRule FixIf using iRule <4.0.0, replace the HSL::open line with two lines: set nn_pool noname-security-hsl-https then set nn_hsl [HSL::open -proto TCP -pool $nn_pool]. v5.0.0 already has this fix.
Step 5 · The On Switch Attach iRule to Application VS Activate
juiceshop_vs → Resources → iRules → Manage

Nothing sends traffic to Noname until this step. Move noname-hsl-https-logger from Available to Enabled.

  • Local Traffic → Virtual Servers → Virtual Server List
  • Click juiceshop_vs
  • Select the Resources tab
  • iRules section → click Manage
  • Move noname-hsl-https-logger → Enabled
  • Click Finished
🚫
Traffic Loop RiskNEVER attach this iRule to noname-security-engine-https-vs — it creates an infinite loop. Only attach to juiceshop_vs.
⚠
iRule Ordering MattersIf another iRule on this VS uses HTTP::respond, place the Noname iRule BEFORE it. If it uses HTTP::collect, place it AFTER.
Step 6 · SSH Save Configuration — Required on BIG-IP v21 (no GUI Save button) Persist
ssh admin@mcropsey-juiceshop-f5.eastus.cloudapp.azure.com tmsh save sys config

Run this after every configuration change. Without it, changes are lost on reboot.

Gotchas & Limitations
⚠ Payload Size Limit
Payloads >128KB are skipped by the iRule entirely. Adjustable via nn_payload_max_size but larger values impact F5 performance.
🚫 SSL Passthrough
SSL Passthrough on juiceshop_vs means the iRule cannot read encrypted traffic. F5 must terminate (offload or bridge) SSL for this integration to work.
ℹ F5 Version Bug
BIG-IP 14.1.4.6 and 14.1.5.x with HTTP chunking enabled may have issues. Also: integration may count against your F5 license bandwidth.
